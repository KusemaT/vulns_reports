## Title

Remote Code Execution via [Command Injection] on [diagnostics endpoint]

## Vulnerability Type

Remote Code Execution (RCE)

## Summary

Nexusforge [https://kzlabs.in/subdomains/diagnostics/] is vulnerable to remote code execution.
The application fails to properly validate/sanitise [user input passed to a system command] before processing it, allowing an attacker to execute arbitrary commands/code on the underlying server. This can lead to full compromise of the host, including access to sensitive data, other applications on the server, and the internal network.

## Vulnerable Endpoint

`https://kzlabs.in/subdomains/diagnostics/` 

1. Navigate to the following URL / functionality: `https://kzlabs.in/subdomains/diagnostics/`
2. Submit the payload below via [command parameter]
3. Access the uploaded/executed payload at `https://kzlabs.in/subdomains/diagnostics/?cmd=cat+%2Fetc%2Fpasswd` and observe that the injected command/code is executed on the server (e.g. output of `id`, `whoami`, or a webshell interface is returned)

## Payload used

`cat /etc/passwd`

(Other useful payloads to demonstrate impact, depending on vector: a `.php` webshell disguised via extension/content-type bypass containing `<?php system($_GET['cmd']); ?>`, `| id`, `` `id` ``, `$(id)` for command injection, or a crafted serialized object for a deserialization vulnerability)

## Impact

An attacker can perform the following actions using this vulnerability:

- It allows attackers to execute arbitrary operating system commands on the underlying server
- It can lead to full compromise of the server, including reading/modifying/deleting any file the application's process can access
- It can be used as a foothold to pivot further into the internal network
- It allows attackers to access sensitive data, source code, configuration files, and credentials stored on the server
- It can result in complete loss of confidentiality, integrity, and availability of the application and host

## Recommendations for fix

Ensure user-supplied input can never reach a code/command execution context unsanitised. This can be done by:

1. Never pass user-controlled input directly to system commands, `eval()`, or similar dynamic execution functions; use safe, parameterised APIs instead
2. If file uploads are required, strictly validate file type via content inspection (not just extension/MIME type), store uploads outside the web root, disable script execution in the upload directory, and rename files on upload
3. Avoid deserializing untrusted data; if unavoidable, use safe serialization formats (e.g. JSON) and integrity-check/sign serialized objects
4. Run the application with the least privilege necessary (non-root user, restricted file system permissions, containerisation/sandboxing)
5. Keep frameworks, libraries, and server software patched, as many RCE vulnerabilities stem from known CVEs in outdated components
6. Use a WAF (e.g. Cloudflare) as a defence-in-depth measure, though this should not be relied on as the primary fix
